# Project rules

- Old backup cleanup runs inside `runBackup` after a successful backup and only touches `backup_jobs` rows and `backups` bucket files, so no extra scheduled job is needed and app/member data is never affected.
- Admin job takedowns use `jobs.admin_hidden` set only via the `admin_set_job_hidden` RPC, guarded by a trigger and SELECT policies, so employers cannot re-activate a hidden job and every seeker query stays filtered without code changes.
- Ad banners share one `ad_banners` table split by its `audience` column (`seeker` / `employer`), so each admin banner page and each app screen only reads its own audience.
- Public store-download guidance lives in the standalone `/download` route and uses explicit external store links, so visitors can choose a store without signing in or automatic redirection.- Push device registration goes through the `register_native_push_token` / `register_web_push_subscription` RPCs, which reassign an existing token/endpoint to the signed-in user, because owner-only RLS blocks a direct upsert when the same device was used by another account.
- The admin dashboard lives at `/admin/dashboard` (`admin_.dashboard.tsx`), loads all numbers from the admin-checked `getAdminDashboard` server function with Korean-time bucketing in `admin-dashboard.ts`, and refuses to render inside the installed app, so admins can check it from any browser (including phones) while the full `/admin` page stays PC-only.
- Phone numbers are normalized to hyphenated Korean format by the `format_kr_phone` DB trigger on every phone column, and inputs use `PhoneInput` (`src/lib/phone.ts` mirrors the DB logic), so stored values stay consistent no matter which screen or server path saves them.
