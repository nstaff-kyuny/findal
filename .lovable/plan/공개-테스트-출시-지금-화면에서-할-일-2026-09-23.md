# 공개 테스트 출시 — 지금 화면에서 할 일

## 현재 화면 해석
- 위치: **테스트 및 출시 → 공개 테스트 → 출시 버전 생성** 화면
- "개선사항 2개 중 2개 활성 상태"는 AAB 업로드 시 자동 적용되는 개선 기능(예: 대상 SDK 버전)이 모두 켜져 있다는 뜻 → **그대로 두면 됩니다.**
- 아직 **AAB 파일이 업로드되지 않은 상태**입니다 (App Bundle 영역 비어 있음).

## 진행 순서

### 1. 서명된 AAB 준비 (아직 없다면)
윈도우 PC의 Android Studio에서:
1. 프로젝트 열기 (OneDrive 밖 로컬 경로 권장)
2. **Build → Generate Signed App Bundle / APK**
3. **Android App Bundle** 선택 → Next
4. 키스토어: 이전 내부 테스트 업로드에 사용한 키스토어가 있으면 **Choose existing**으로 반드시 동일 파일 사용 (새 키로 만들면 업로드 거부됨)
5. Build variant: **release** → Finish
6. 결과물: `android\app\release\app-release.aab`

### 2. AAB 업로드
- 지금 화면의 **"업로드"** 클릭 → `app-release.aab` 선택
- 처리 대기 (수 분 소요, 버전 코드가 자동 인식됨)
- 처리 중 경고/오류가 뜨면 캡처해서 공유

### 3. 버전 세부정보
- **출시 이름**: 업로드 후 버전 코드로 자동 채워짐 (그대로 사용)
- **출시 노트** (한국어 필수), 예:
  `일용·단기 일자리 매칭 서비스 Find AR의 공개 테스트 버전입니다. 로그인, 공고 탐색, 매칭 신청 기능을 확인해 주세요.`

### 4. 저장 후 출시
1. **다음 → 저장**
2. 우측 상단 **변경사항 검토 → 테스트 출시 시작**
3. 공개 테스트는 Google **신규 앱 검토가 필요**할 수 있으며, 첫 심사는 며칠(통상 1~7일) 소요될 수 있습니다.

### 5. 테스터 확인
1. **공개 테스트 → 테스터 탭**에서 참여 링크(opt-in URL) 확인
2. 테스터 폰에서 링크 열어 등록 → Play 스토어에서 Find AR 설치·실행

## 업로드 전 체크리스트
- [ ] 기존 키스토어(내부 테스트와 동일)로 서명했는지 확인
- [ ] 버전 코드가 이전 업로드보다 큰지 (동일 버전 코드면 업로드 거부)
- [ ] 키스토어 .jks + 비밀번호 + alias 백업 보관
