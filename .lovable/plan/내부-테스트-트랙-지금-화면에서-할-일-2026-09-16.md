# 내부 테스트 트랙 — 지금 화면에서 할 일

## 현재 화면 해석
- 지금 있는 곳: **테스트 및 출시 → 내부 테스트 → 출시 탭**
- 위에 뜬 안내 박스("앱의 이름이 이 버전에 부여됨")는 단순 정보 표시입니다.
  - 뜻: 내부 테스트 버전에서는 앱 이름을 릴리스마다 직접 정하지 않고, 스토어 등록정보에 저장된 **"Find AR"** 이름이 그대로 표시된다는 의미.
  - **할 일 없음** — 그대로 두면 됩니다.

## 진행 순서

### 1. 서명된 AAB 준비 (가장 먼저, Android Studio에서)
아직 AAB 파일이 없으면 업로드할 수 없습니다.
1. Android Studio에서 프로젝트 열기 (OneDrive가 아닌 `C:\Projects\FindAR` 같은 로컬 경로 권장)
2. 메뉴 **Build → Generate Signed App Bundle / APK**
3. **Android App Bundle** 선택 → Next
4. 키스토어: 없으면 **Create new...** 로 생성
   - Key store path, password, alias 기록 후 **반드시 백업** (분실 시 업데이트 불가)
5. Build variant: **release** → Finish
6. 결과물: `android/app/release/app-release.aab`

### 2. 내부 테스트 트랙 설정 (테스터 등록)
1. 왼쪽 메뉴 **내부 테스트** 클릭 → 상단 탭에서 **테스터** 탭 선택
2. **이메일 목록 만들기** → 목록 이름 지정(예: `내부 테스터`) → 테스트할 Gmail/Google 계정 이메일 추가 (본인 계정 포함, 최대 100명)
3. 저장하면 **참여 링크(opt-in URL)**가 생성됨 — 이 링크를 테스터 폰에서 열어 "테스터 등록" 후 Play 스토어에서 설치

### 3. 새 버전(릴리스) 만들기
1. **출시** 탭에서 **"새 버전 만들기>"** 클릭 (현재 화면에 보이는 버튼)
2. **Google Play 앱 서명** 안내가 나오면 그대로 진행 (첫 AAB 업로드 시 자동으로 Play 앱 서명 등록됨)
3. **앱 번들** 영역에 `app-release.aab` 파일 드래그/업로드
4. 업로드 처리 대기 (수 분 소요, 처리 중 경고가 있으면 내용 확인)
5. **출시 이름**: 업로드하면 버전 코드로 자동 채워짐 (그대로 사용 가능)
6. **출시 노트**: 한국어로 간단히 작성
   - 예: `첫 내부 테스트 버전입니다. 로그인, 공고 탐색, 매칭 신청 기능을 확인해 주세요.`
7. **다음 → 저장** 후 우측 상단 **변경사항 검토 → 테스트 출시 시작** 클릭
   - 내부 테스트는 Google 검토 없이 **즉시 배포**됩니다.

### 4. 테스터 폰에서 확인
1. 테스터 이메일로 2단계의 **참여 링크** 열기 → "테스터가 되기" 탭
2. Play 스토어에서 **Find AR** 검색 후 설치 (최대 몇 분 소요될 수 있음)
3. 앱 실행 → 구직자/구인자 로그인 및 핵심 화면 동작 확인

## 업로드 전 체크리스트
- [ ] 서명된 AAB 생성 완료 (`app-release.aab`)
- [ ] 키스토어 백업 완료
- [ ] 테스터 이메일 목록 등록
- [ ] 버전 코드 1, versionName 1.0 확인 (이후 업데이트 시마다 증가)
- [ ] 출시 노트 한국어 작성

## 병행 작업 (내부 테스트와 무관하게 진행 가능)
내부 테스트 출시는 **대시보드 체크리스트가 다 완료되지 않아도 진행할 수 있습니다.**
프로덕션 출시 전에는 아래 항목을 마쳐야 하므로 AAB 업로드와 병행하세요.
- 대시보드 → 앱 설정: 앱 접근 권한, 광고(없음), 콘텐츠 등급, 타겟층, 데이터 보안, 개인정보처리방침, 카테고리·연락처
- 개인정보처리방침: `https://findar.nstaff.co.kr/privacy` (이미 배포됨)
- 계정 삭제 링크: `https://findar.nstaff.co.kr/delete-account` (이미 배포됨)
