# Find AR 앱스토어 · 플레이스토어 등록 준비

현재 프로젝트는 웹앱(PWA)입니다. 네이티브 래퍼가 없어서 지금 상태로는 두 스토어에 제출할 수 없습니다. Capacitor로 iOS/Android 앱을 감싸는 방향으로 준비합니다.

## 1) 계정 준비 (코드와 병행, 가장 오래 걸림)

- Apple Developer Program: 연 $99. 법인 명의(주식회사 엔스태프)로 등록하려면 **D-U-N-S 번호**가 필요하고 발급에 1~2주, 심사에 추가 1~2주가 걸립니다. 먼저 시작하세요.
- Google Play Console: 1회 $25. 법인 계정은 사업자등록증·D-U-N-S 등 조직 확인이 필요하고, 2023년 이후 개인 계정은 12명 내부 테스터 14일 테스트 요건이 있어 **조직(법인) 계정 등록을 권장**합니다.
- 결제 관련: 앱 내에서 크레딧(디지털 재화)을 판매하므로 **Apple/Google 인앱결제 정책이 적용될 수 있습니다.** 대응 방향은 아래 4)에 정리했습니다.

## 2) 스토어별 진행 순서 요약

Android (Play)
1. Play Console 앱 생성 → 패키지명 확정(예: `kr.co.nstaff.findar`)
2. Capacitor Android 프로젝트 생성 → 아이콘/스플래시/버전 설정
3. 서명 키 생성 + Play 앱 서명 등록 → AAB 빌드
4. 스토어 등록정보(설명, 스크린샷 4장 이상, 512 아이콘, 1024x500 피처 그래픽)
5. 데이터 보안 설문, 콘텐츠 등급, 광고 여부, 대상 연령
6. 내부 테스트 → 비공개 테스트 → 프로덕션 심사(보통 1~7일)

iOS (App Store)
1. App Store Connect 앱 생성 + Bundle ID 등록
2. Capacitor iOS 프로젝트 → Xcode에서 아이콘/스플래시/권한 문구 설정
3. 푸시 인증서(APNs Key) 생성, Push Capability 활성화
4. Archive → TestFlight 업로드
5. 스토어 정보(설명, 스크린샷 6.7"/6.5"·iPad, 개인정보 처리방침 URL, App Privacy 설문)
6. 심사 제출(보통 1~3일, 리젝 대응 여유 필요)

## 3) 이번에 코드로 작업할 것

- **Capacitor 도입**: `@capacitor/core`, `@capacitor/cli`, `@capacitor/ios`, `@capacitor/android` 추가, `capacitor.config.ts` 작성. 앱 ID `kr.co.nstaff.findar`, 앱 이름 `Find AR`.
- 배포된 웹(https://findar.nstaff.co.kr)을 로드하는 하이브리드 구성(`server.url`) 기준으로 설정하고, 완전 번들 방식으로 전환할 수 있도록 주석·문서화.
- **네이티브 푸시 대응**: 현재 웹푸시(`src/lib/push-client.ts`)는 브라우저 전용. 네이티브에서는 `@capacitor/push-notifications`로 토큰을 받아 같은 구독 테이블에 저장하도록 플랫폼 분기 추가. iOS 웹푸시(홈화면 추가 필수) 안내 문구는 네이티브 앱에서는 숨김.
- **딥링크/OAuth**: 구글 로그인 리다이렉트가 네이티브 웹뷰에서 끊기지 않도록 `@capacitor/browser` + 커스텀 스킴/Universal Link 처리.
- **뒤로가기·상태바·세이프에어리어**: Android 하드웨어 백버튼 처리, 상태바 색상, `env(safe-area-inset-*)` 재검토.
- **계정 삭제 기능 노출**: 두 스토어 모두 회원가입이 있는 앱에 **앱 내 계정 삭제 경로**를 요구합니다. `account.functions.ts`에 로직이 있는지 확인해 설정 화면에서 명확히 접근 가능하게 정리.
- **문서 URL**: 개인정보처리방침·이용약관·환불정책이 로그인 없이 열리는 공개 URL로 접근 가능한지 확인(스토어 심사 필수 입력값).
- 앱 아이콘/스플래시 원본(1024x1024) 및 스토어 스크린샷용 에셋 생성.

## 4) 심사 리스크와 대응 (중요)

- **크레딧 결제**: iOS는 앱 내에서 디지털 재화(크레딧)를 팔면 원칙적으로 인앱결제(수수료 15~30%)를 요구합니다. 현재는 토스페이먼츠 웹 결제입니다. 선택지:
  a. 구인자용 결제는 앱에서 제거하고 PC 웹(`/manager`)에서만 진행 → 앱은 조회·매칭 전용(리스크 최소).
  b. iOS만 인앱결제 추가(개발량 큼).
  c. 구인자 앱은 "비즈니스/기업용" 예외 주장 → 리젝 가능성 있음.
  권장: 우선 (a)로 제출하고 이후 확장.
- **로그인 필수 화면**: 심사용 데모 계정(구직자/구인자) 제공 필요.
- **최소 기능성**: "웹사이트를 그냥 감싼 앱"은 iOS 4.2 리젝 사유가 됩니다. 푸시 알림·홈화면 위젯 수준의 네이티브 통합(최소 네이티브 푸시)을 반드시 포함해야 합니다.
- **개인정보 수집 설문**: 이름·이메일·전화·국적·비자상태까지 수집하므로 App Privacy / 데이터 보안 설문에 정확히 기재해야 합니다.

## 5) 제안 순서

1. 계정 개설 착수(오늘 시작)
2. Capacitor 도입 + 네이티브 푸시/딥링크/백버튼/계정삭제 정비
3. iOS 결제 정책 방향 결정 후 앱 내 결제 노출 조정
4. 아이콘·스플래시·스크린샷 에셋 제작
5. 내부 테스트(TestFlight / Play 내부 테스트) → 심사 제출

빌드·서명·업로드 자체는 Mac(Xcode)과 Android Studio가 있는 로컬 환경에서 진행해야 하며, 그 단계별 명령어도 함께 정리해 드립니다.
